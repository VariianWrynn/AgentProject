# 口头应答库 — 对话面试专用

> 对话面试的失败模式不是"被查出来"，是**自己前后矛盾**。面试官验证不了数字，但记得住你二十分钟前说过什么。
> 所以：数字要少而固定，故事要具体，边界要主动交代。
> 本文写的是**口语**，不是书面语——照着念应该是自然的。

---

## 一、数字速记卡（必须张口就来，且互相不打架）

| 场景 | 说法 |
|------|------|
| 语料规模 | 三十七篇，九万多字，切成一百三十八个块，跨度二一到二六年 |
| 检索 | 三十道题里命中二十九道，hit@5 大概九成七 |
| 意图分类 | 五十道题对四十四道，八成八 |
| 事实性错误率 | 四十道题，改造前错十一道、改造后错六道，从两成七降到一成五 |
| 无据作答 | 十道语料外的题，改造前七道瞎编，改造后只剩一道 |
| 守卫拦截 | 首稿拦下五十二处，回炉重写二十六个章节，最后还有十八处标了"未核验" |
| 提速 | 并行加缓存，三条 query 逐个比，中位一点五七倍 |
| 成本 | 大小模型分级省一成二，但**不提速** |
| 记忆检索 | 相关问题零点六八，完全无关的零点三三，差两倍 |

**只用这九组。** 被从不同角度问到同一件事时，三次回答必须收敛到同一个数。

## 二、签名故事四条（各证明一种特质，60–90 字，可主动抛出）

### 故事 A：索引选型 —— 证明"测量纪律"

> "我一开始照教程用了 IVF 索引，nlist 设一千零二十四。后来发现我库里总共才一百六十一个向量——平均每个簇零点一三个，而且 nprobe 只搜百分之六的簇，我怀疑它在悄悄丢召回。于是换成 FLAT 暴力检索重测。**结果我猜错了**，两种索引召回一模一样，逐题排名零差异，Milvus 在小集合上已经做了退化处理。我还是换成了 FLAT——IVF 那两个参数在这个量级没有意义，留着会误导后面读代码的人。"

**这条最好用**，因为它讲的是"假设被数据推翻"，比"我修了个 bug"更能体现你不是拍脑袋的人。

### 故事 B：幻觉的真实样子 —— 证明"问题是真的"

> "有道题问比亚迪二三年营收多少，我的语料里根本没有比亚迪。改造前系统很自信地写了'约六千零二十三点一五亿元'，一个引用都没有。数字对不对我都不知道——**关键是它没有出处**。改造后同一道题，它只引用冻结证据里有的宁德时代数字，比亚迪那部分不编了。"

细节（6023.15）是可信度的来源，编不出来这种数。

### 故事 C：抓取踩坑 —— 证明"工程韧性"

> "政策全文最难抓。发改委的页面是政务系统模板，trafilatura 从一百多 K 的 HTML 里只抽出六十二个字。我去看 DOM 才发现正文挂在一个叫 UCAP-CONTENT 的容器里，就加了一层中文 CMS 选择器的级联回退——同一篇从六十二字变成一万一千多字。财经门户是另一个坑，抓宁德时代那篇八成内容是无关的新闻推荐，得按尾部标记截断。"

### 故事 D：数据严谨 —— 证明"你会怀疑自己的数据"

> "有一篇聚合站标着'中国神华 2023 年报'，我核对数字的时候发现里面写的是二二年的营收。如果我不查就把它当评测集的标准答案，后面所有指标都被污染了。我把它改名成二二年，评测集里每条引文我都要求能在原文里逐字搜到，还写了个测试专门防这个。"

## 三、口头应答库

### 关于评测

**Q：错误率从两成七降到一成五，这个提升显著吗？**
> "统计上不显著。四十道题，错十一道对错六道，我算过 Fisher 精确检验，p 值零点二七。我拿它当方向性证据——机制确实在起作用，但要下强结论得把评测集扩到两百题以上。这也是我下一步想做的事。"

**Q：hit@5 九成七，分母多少？题目谁出的？**
> "三十道，我自己出的，而且是**对着语料出的**——每道题的证据原文我都逐字锚定过。所以它有乐观偏差：它证明的是检索链路通、embedding 没问题，不代表真实场景的绝对召回。真要评召回，得用不看语料的人出的题。"

**Q：那道没命中的题是什么情况？**
> "通威二四年三季度盈亏那道。检索返回的是通威的财报文档，其实挺合理；但我标的标准答案指向一篇多晶硅价格文章——那句亏损数据只是顺带出现在里面。所以**是我标注的问题**，不是检索失败。跨文档的事实用单一标准文档去标，本来就不严谨。"

**Q：0.68 的相关度算高吗？**
> "我补了对照才敢说。相关问题平均零点六八，完全无关的问题——比如问意大利面怎么煮——平均零点三三，差两倍。零点五这个阈值正好卡在中间。单看零点六八确实说明不了什么，得有地板分做对照。"

### 关于架构

**Q：为什么要拆成六个角色？**
> "单个 ReAct 循环里规划、检索、写作、审查全混在一起，报告质量一波动我根本不知道是哪一环坏了。拆开之后每个角色状态是显式的，关键环节能单独测——比如 Router 的意图准确率、LeadWriter 的引用违规率、CriticMaster 的检出率，这三个我都有数。"

**Q：怎么并行的？**
> "两种机制。检索那层是 asyncio，因为几个子问题的搜索是纯 IO 等待。章节写作用的是线程池——LLM 的 SDK 是同步调用，asyncio 包不住，只能靠线程。合起来单份报告中位快一点五七倍。"

**Q：模型分级提速多少？**
> "**不提速。** 这是个反直觉的结果——我逐条 query 比过，三条里有两条分级之后反而更慢。它的价值在成本，省一成二。提速全部来自并行和缓存，这两件事不该混在一起说。"

**Q：省一成二是不是有点少？**
> "少，而且上限就在这儿。token 的大头在写作和审查环节，这两个必须用大模型，能降级的只有路由、检索、分析这些轻活儿。所以我说的是'省一成二且零质量代价'，不是'成本砍半'。"

**Q：为什么不用 AutoGen 或者 MetaGPT？**
> "我要的是确定性编排，不是自由对话式协作。我那个事实约束机制要在'检索完'和'开始写'之间插一道证据冻结，LangGraph 的状态机能明确挂载这个点，AutoGen 的 agent 自由对话没有稳定的中间表示，没地方挂。另外降级路径要走条件边，这个也得图结构显式表达。反过来说，如果是开放式探索问题，AutoGen 那种模式确实更合适。"

**Q：语料才九万字，为什么不直接塞长上下文？**
> "这个质疑成立——九万字大概十三万 token，一兆上下文确实塞得下。我选检索不是因为塞不下，是因为**要可审计**。我的校验机制靠 chunk_id 把每个数字锚回原文，全文塞进去就没有这个锚点了。我也承认，在这个规模上 RAG 的成本优势还没体现出来，它是设计取舍不是规模逼出来的。"

### 关于可靠性

**Q：三层降级你怎么验证的？**
> "有一次跑测试的时候 MCP 服务恰好没开，反而验证了两层：工具层自动降级成本地函数，流水线层退回老的 ReAct 图，最后还是出了一份五百多字有依据的答案，四步执行，置信度零点九五。不过我得说清楚——我只真实注入过'MCP 离线'这一种故障，LLM 超时和 Text2SQL 失败那两条路径目前只有单测覆盖。"

**Q：校验不过就重写，重写有效吗？**
> "五十二处首稿违规，重写修好三十四处，大概六成五。剩下十八处我不静默放行，直接在报告里标'未通过证据核验'。我宁愿它显得难看，也不要一句看起来很确定但没依据的话混进去。"

### 关于项目本身

**Q：这个是给谁用的？有真实用户吗？**
> "没有外部用户，我自己是使用者。但评测里那四十道题都是真实分析场景会问的问题——查财报数字、查政策条款、汇总市场数据。我更愿意说它是'冻结且可复现的评测'，而不是'给朋友用过'，因为前者你随时能让我重跑。"

**Q：从二五年六月到现在，十四个月做了这些？**
> "前期是课程学习和本地原型，没进仓库。二六年三月开始工程化，仓库记录是从那时候起的——五个月二十多个 PR。中间四月底做完多智能体之后有一段是我自己在用，八月这次重构就是用的过程中发现数字不可信才立的项。"

## 四、AI 辅助怎么答（三个调子，挑一个改成你自己的话）

> 你的 commit 全部带 `Co-Authored-By: Claude`，对方翻 git log 就看得到，所以**必须主动、坦然**。三个版本强度递增：

**版本 A — 工具论（最保守）**
> "写代码基本都用 Claude Code，我把它当一个很强的结对编程搭档。但技术选型、评测怎么设计、数字能不能信，这些判断是我的。"

**版本 B — 方法论（推荐）**
> "代码大部分是 AI 写的，我不回避这个。我的价值在于**定义什么算对**——比如那套事实性评测集，四十道题的标准答案是我逐条对着语料核的，还写了测试防止 AI 编造引文。AI 能写实现，但它不知道该拿什么标准验收。"

**版本 C — 坦率量化（最强，但有前提）**
> "实现层面八成以上是 AI 写的。我做的是三件事：定架构和降级策略、设计评测口径、以及**推翻它的结论**——比如它把一次性能对比的中位数跨运行拼在一起算出个一点六六倍提速，我逐条 query 复算之后发现只有一点五七倍，而且模型分级根本不提速。这种事只能靠人去查。"

**⚠️ 选 C 的前提**：那些"推翻"必须真的是你要求核查的。如果实际是我主动发现并告诉你的，就选 B——B 已经足够强，而且完全经得起追问。**这句话是关于你怎么工作的陈述，得是真的。**

## 五、如果对方真要求看东西（低概率，备用）

挑一个带 `[E5]` 的数字 → 翻到附录的引用对照表找到 chunk_id 和来源 → 打开对应语料文件搜这个数字 → 逐字命中。
