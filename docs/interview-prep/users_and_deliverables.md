# 目标用户与交付物定义

## 目标用户（如实口径）

**定位**：能源行业的个人分析场景——研究员/投研助理级别的"每日案头调研"。

**实际使用**：我自己作为分析场景用户使用——固定评测集里的 40 个真实行业问题（财报数字核对、政策条款查询、市场数据汇总）+ 3 份完整样例报告，全部真跑真验。没有外部用户，不虚构；但每个问题都是真实分析工作流里会问的问题（"宁德时代 2023 年营收多少""136 号文对存量项目怎么划分""2024 年储能装机到多少了"）。

**一句话**："用户是我自己扮演的能源分析师，但评测是冻结且可复现的——这比'给朋友用过'更有说服力，因为数字可以当场重跑。"

## 交付物：报告长什么样

| 维度 | 说明 |
|------|------|
| 结构 | 标题 + 质量评分 + 执行摘要 + 2-5 个分析章节 + 参考来源列表 |
| 来源数 | 每份报告冻结 11-13 条证据（RAG chunk + Bocha 网页），参考列表按 [E*] 标签对应 chunk_id/URL |
| 引用粒度 | 句级——每个含数字的句子尾注 [E3] 式证据编号，可回指到 Milvus chunk 原文精确核对 |
| 质量控制 | CriticMaster 审查 + 质量分 <0.7 触发 HITL 人工门控；引用校验不过的表述显式标注"未核验" |
| 产出耗时 | demo 模式 ~20-45s；完整模式见 perf 报告（⏳ 回填） |
| 样例 | docs/reports/sample_reports/ 3 份（政策/财报/市场各 1），面试现场可展示 |

## 面试展示动线（2 分钟）

1. 打开一份样例报告 → 指一个带 [E5] 的数字
2. 打开 references → 找到 E5 的 chunk_id 和来源 URL
3. 打开对应语料 clean/ 文件 → grep 这个数字，逐字命中
4. 收尾："这条链路是评测保证的——40 题评测里无据作答率 10%，剩下的都标了'未核验'。"
